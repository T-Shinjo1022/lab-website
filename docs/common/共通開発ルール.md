# 共通開発ルール

## 開発方針
既存リポジトリの技術構成・命名規則を優先します。新規フレームワーク導入や共通部品の大幅変更はA（リーダー）と相談してください。

## 共通部分
Aが共通ヘッダー、フッター、ナビゲーション、共通CSS/JS、全体統合を担当します。他の担当者は、ページ固有のコード・文章・画像を中心に作業してください。既存の共通コンポーネントを再利用し、ページごとに独自ヘッダーを作らないでください。

## デザイン
- 見出し、本文、色、余白、カード、ボタンの雰囲気を統一する。
- PCとスマートフォンの両方に対応する。
- 画像を引き伸ばさず、適切な代替テキスト（alt）を設定する。
- 動きや装飾は読みやすさを損なわない範囲にする。
- ゼミページは同じテンプレートを基本とする。

## 内容
- 実際に確認できた情報だけを掲載する。
- AIに研究内容、実績、設備、人数、イベント、教員の趣味、進路を創作させない。
- 文章・キャッチコピーはAIに提案させてもよいが、事実の正確性を確認する。
- 文章や画像は、後から差し替えやすい場所にまとめる。
- 個人情報、写真、論文の掲載可否と権利を確認する。
- 不明な項目は `[要確認]` と記載する。

## GitHub
作業ブランチ → コミット → PR → レビュー → マージの流れを守る。共通ファイルの変更はAと事前調整する。

## AIの使い方
最初に既存コードを確認させ、変更予定ファイルを説明させる。実装後は変更点、コードの役割、文章・画像の差し替え場所、動作確認方法を説明させる。実行していないテストを「確認済み」と書かせない。

## PRチェック
- [ ] 担当範囲の変更のみ
- [ ] 未確認の事実なし
- [ ] PC・スマートフォンで表示確認
- [ ] 画像・リンクの動作確認
- [ ] 共通デザインと統一
- [ ] PR説明とスクリーンショットを添付
