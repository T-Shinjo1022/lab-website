## 最初にお願いすること
1. リポジトリの構成、使用技術、共通部品、既存ページを確認する。
2. 既存のデザイン・コーディング規則を説明する。
3. 変更するファイルと変更理由を提示する。
4. 不明な事実や仕様は質問する。いきなり大規模変更をしない。

## 実装条件
- 既存の技術構成を維持する。
- 共通ヘッダー・フッター・共通CSS/JSはAが担当するため、勝手に作り直さない。
- 担当範囲を超える変更が必要なら事前に知らせる。
- 研究室・教員・学生・研究・設備・進路・業績・イベントに関する事実を創作しない。
- 未確認情報は `[要確認]` などで明示する。
- 文章・キャッチコピーは後から差し替えやすくする。
- PCとスマートフォンの表示に対応する。
- ゼミページでは他のゼミと共通の構成を使う。

## 文章とデザイン
まずレイアウト案を簡潔に示し、キャッチコピーを3〜5案、各案の狙いとともに提案してください。採用する案を相談した後、コードを実装してください。文章は提供情報から作り、事実を追加しないでください。

## 実装後の説明
- 変更したファイルと役割
- コードの重要部分の説明（初心者向け）
- 文章・画像・色・余白の変更場所
- 起動・テスト・表示確認の手順
- 未確認事項と残タスク
- PRに貼る変更概要

私はAIに任せきりにせず、コードを理解して改善することも目標にしています。
