# 研究室webサイト 開発プロジェクト

## 1. プロジェクト概要

本プロジェクトでは、GitHubとAIを活用し、グループでWebサイトを制作することを通じて、実践的な開発経験を身につけることを目的とします。

最終的な成果物として、[大学名] [研究室名] のホームページを制作します。

ただし、この活動で最も重視するのは、ホームページを完成させることだけではありません。制作過程を通じて、GitHubを使ったチーム開発や、AIを活用したプログラミングの進め方を学ぶことを主な目的とします。

## 2. 活動の目的

本プロジェクトでは、次の3点を学習の柱とします。

### ① GitHubの活用

GitHubを利用した共同開発の基本を身につけます。

- リポジトリの作成・管理
- ブランチを使った開発
- コミットによる変更履歴の管理
- Pull Request（プルリクエスト）による変更の提案
- 他のメンバーのコードの確認と統合
- GitHub上での情報共有や意見交換

### ② グループでの制作

複数人で一つのWebサイトを制作する経験を通じて、チーム開発の進め方を学びます。

- 制作するWebサイトの構成やデザインを話し合う
- ページや機能ごとに役割を分担する
- 各自が担当部分を開発する
- 他のメンバーの成果物と統合する
- 意見を出し合い、問題を解決する

### ③ AIによるコード作成

生成AIをプログラミングの補助として活用し、効率的な開発方法を学びます。

- AIに要件やデザインを伝えてコードを作成する
- 生成されたHTML・CSS・JavaScriptの内容を理解する
- 実際にブラウザで動作を確認する
- 不具合が発生した場合、原因を調べて修正する
- AIの出力をそのまま採用せず、自分たちで確認・改善する

## 3. 最終目標

活動の最終目標は、**見た人が研究室に興味を持ち、「この研究室に行ってみたい」と感じられるホームページを完成させること**です。

研究内容や研究室の雰囲気、ゼミ活動、イベントなどを紹介し、研究室の魅力が伝わるWebサイトを目指します。

見た目の美しさだけでなく、情報の分かりやすさや使いやすさ、スマートフォンでの閲覧にも配慮します。

## 4. 制作するWebサイトの構成

現時点では、以下のページを制作する予定です。

| ページ | 主な内容 |
|---|---|
| HOME | 研究室の概要、各ページへの案内 |
| 研究室紹介 | 研究室の目的、設備、研究方針など |
| メンバー | 教員・学生の紹介、研究テーマ |
| ゼミ紹介 | 各ゼミの内容、活動風景、研究紹介 |
| イベント | 学会、行事、レクリエーションなど |
| 研究室を希望する学生へ | 研究室の魅力、学生の声、ゼミの雰囲気 |
| 先生の個人的な情報 | 先生の趣味など |
| アクセス | 所在地、連絡先など |

※ページ構成は、制作を進めながら必要に応じて変更します。

## 5. 開発方針

本プロジェクトでは、1つのGitHubリポジトリを全員で共有し、ページごとに担当を分けて開発します。

基本的な開発の流れは以下のとおりです。

1. 担当するページや機能を決める
2. GitHubから最新のコードを取得する
3. 自分の担当用ブランチを作成する
4. AIを活用してコードを作成・修正する
5. ブラウザで表示や動作を確認する
6. GitHubに変更をPushする
7. Pull Requestを作成する
8. 内容を確認し、問題がなければ統合する

### 開発時のルール

- `main` ブランチに直接変更を加えない
- 作業ごとにブランチを作成する
- 担当外のファイルは、事前に相談せず変更しない
- 共通部分のデザインや構造は、メンバー間で統一する
- Pull Requestを作成してから統合する
- AIが生成したコードも、必ず内容を確認してから提出する

## 6. AIを利用する際の方針

AIはコードを作成するための便利な補助ツールですが、コードの理解をAIに任せきりにしないことを大切にします。

各自が以下の点を意識して開発します。

- AIに具体的な指示を出す
- 生成されたコードの役割を理解する
- 分からない部分はAIに質問する
- 表示崩れやエラーがないか確認する
- 必要に応じて自分でコードを修正する

最終的には、作成したページについて、どのような仕組みで動いているのかを自分の言葉で説明できることを目指します。

## 7. プロジェクトの進め方

活動は、以下の流れで進める予定です。

1. **企画・設計**：サイトの目的、構成、デザインを決める
2. **環境構築**：GitHubの使い方や開発環境を確認する
3. **ページ制作**：担当者ごとにAIを活用して開発する
4. **統合・確認**：Pull Requestを通じてコードを統合する
5. **改善**：デザインや操作性、掲載内容を見直す
6. **完成・公開**：最終確認を行い、ホームページを公開する

## 8. この活動で大切にすること

本プロジェクトでは、完成したホームページだけでなく、そこに至るまでの過程も成果として大切にします。

- GitHubを実際に使いながら覚える
- 分からないことをメンバー同士で共有する
- AIを活用しながら、自分で考えることを忘れない
- 失敗やエラーを経験し、解決方法を学ぶ
- 全員が制作に参加し、一つの成果物を完成させる

**「AIに作ってもらう」だけではなく、「AIを活用して、自分たちで作れるようになる」ことを目指します。**
