# 役割分担と進行管理

## 担当一覧
| 区分 | 担当者 | 主な担当 | 共同作業時の注意 |
|---|---|---|---|
| A | リーダー | HOME、共通ヘッダー・フッター、共通CSS/JS、統合、VRゼミ、教員個人紹介 | 共通部分の窓口・統合担当 |
| B | Ujita | モーションシャープニングゼミ、研究室紹介 | ページ固有部分を担当 |
| C | Yamamoto | デザインゼミ、アクセス、進路 | ページ固有部分を担当 |
| D | Haga | モーションゼミ、イベント | ページ固有部分を担当 |
| E | Sakudou | メンバー、学生・教員の論文、配属希望者向け | ページ固有部分を担当 |

## ファイルの責任範囲
- **A（リーダー）**：HOME、VRゼミ、共通ヘッダー・フッター、共通CSS/JS、ナビゲーション、全ページの統合。
- **B（Ujita）**：研究室紹介、モーションシャープニングゼミ。
- **C（Yamamoto）**：デザインゼミ、アクセス、進路。
- **D（Haga）**：モーションゼミ、イベント。
- **E（Sakudou）**：メンバー、論文・研究業績、配属希望者向け。

## 依存関係・調整事項
1. Aが先に共通ヘッダー、フッター、CSSの基本ルール、ページへのリンク方針を共有する。
2. ゼミの各担当は共通のゼミ紹介テンプレートを利用する。ゼミ一覧の構成はAと相談する。
3. Eの論文一覧から各メンバー・研究テーマへのリンクは、B・各ゼミ担当と整合させる。
4. CのアクセスページとEの配属希望者向けページは、見学・問い合わせ導線をそろえる。
5. AのHOMEは、各担当ページの情報が揃い次第、リンクや紹介カードを更新する。
6. 教員の個人紹介ページの担当・独立ページ化の要否は未決定。チームで確認する。

## GitHub運用
- `main` に直接コミットしない。担当ごとに `feature/home`、`feature/research-lab` などのブランチを使う。
- PRは小さく分け、タイトル・変更点・スクリーンショット・動作確認・未完了事項を書く。
- 共通ファイルに変更が必要なら、先にAへ相談する。
- マージ前にAが表示・リンク・共通デザイン・競合を確認する。
- 各自がAI生成コードの仕組みを説明できることを目標にする。

## ゼミごとの進捗共有
各担当は毎回、**完了したこと／進行中／困っていること／次回までにすること**を共有する。

- [ ] 写真・個人情報の公開許可を確認済み
- [ ] スマートフォンとPCで確認済み
